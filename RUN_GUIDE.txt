# Activity 5 - Query Board Dashboard (Sky Blue & White)

The React dashboard opens directly to Query Board. It follows the supplied reference: no sidebar, four summary cards at the top, 15 numbered visualizations below, and a vertically scrollable page.

## 1. Prepare the database
1. Start Apache and MySQL in Laragon.
2. Create a MySQL database (for example: activity_5_wst_dashboard).
3. In the project root, copy `.env.example` to `.env`.
4. Set DB_CONNECTION=mysql, DB_DATABASE, DB_USERNAME, and DB_PASSWORD for your local MySQL setup.

## 2. Install and run Laravel
Open a terminal in the project root (the folder containing `artisan`):

```powershell
composer install
php artisan key:generate
php artisan optimize:clear
php artisan migrate --seed
php artisan route:list --path=api
php artisan serve
```

API endpoint: http://127.0.0.1:8000/api/v1/products/queries

## 3. Install and run React
Open a SECOND terminal:

```powershell
cd react-frontend
npm install
npm start
```

Open the React URL shown in the terminal (usually http://localhost:3000).

## 4. If Laravel uses another address
Create `react-frontend/.env` and set:

```env
REACT_APP_API_URL=http://127.0.0.1:8000/api/v1/products/queries
```

Restart React after changing this value.

## Dashboard visualizations
1. Products by Category — donut chart
2. Monthly Order Trend — line chart
3. Revenue by Category — vertical bar chart
4. Orders by Category — funnel chart
5. Top 10 Best-Selling Products — horizontal bar chart
6. Average Price by Category — radar chart
7. Reviews Over Time — lollipop chart
8. User Registration Trend — area chart
9. Orders per User — pie chart
10. Review Rating Distribution — waffle chart
11. Product Price vs. Reviews — scatter plot
12. Revenue Trend — step chart
13. Category Contribution to Total Orders — treemap
14. Order Value Distribution — violin plot
15. Cumulative Revenue — waterfall chart

The database schema has no order status column, so the dashboard does not fabricate order statuses. If tables are empty, run `php artisan migrate --seed` after checking database settings. Do not use `migrate:fresh` if you need to preserve existing data.
